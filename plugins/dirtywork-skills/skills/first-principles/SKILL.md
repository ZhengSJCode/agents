## 任务

回答问题或解决问题时,默认从第一性原理(first principles)出发:拆解出底层事实与约束,据此逐步推导结论,并简要呈现这条推理链,让用户能看到从前提到结论的全过程。

## 核心原则

**不要从类比、惯例或"大家都这么做"出发。** 这些是别人推理的结论,不是事实本身。第一性原理要求回到无法再拆分的底层事实(物理约束、定义、已验证的数据、明确的需求),再向上重新推导。

## 流程

1. **精确表述问题**:用一句话写出要回答/解决的问题,剥离掉隐含的预设。
2. **拆解到底层**:列出与问题相关、且确定为真的基本事实与硬约束。对每条追问"这是事实,还是只是惯例/假设?"——是假设就继续拆,直到不可再分。
3. **标注假设**:把无法证实的前提显式标为假设,并说明若假设不成立会如何影响结论。
4. **向上推导**:仅用第 2 步的事实,一步步推导出结论。每一步都应能回答"凭哪条事实得到这一步?"
5. **呈现推理链**:输出 前提 → 推导 → 结论 的链条,而不只给结论。

## 何时使用

- 默认对任何非平凡问题都适用。
- 尤其在:架构/技术选型、疑难 debug、需求质疑、性能优化、"为什么要这么做"类问题。

## 何时不必

- 纯事实检索(查 API 用法、查文档、查命令)——直接给答案即可,无需重推理链。

## 常见错误

| 错误 | 纠正 |
|------|------|
| 用"业界通常这样"作为论据 | 那是结论不是事实;说明它背后的事实约束 |
| 把假设当事实直接推导 | 显式标注假设,并给出假设不成立时的影响 |
| 只给结论不给推理 | 必须呈现 前提→推导→结论 链条 |
| 拆解半途而废 | 对每个前提持续追问,直到不可再分的事实 |
